# AI-based-Forecasting-of-the-Hammer-Prices-at-Art-Auctions
Forecasting auction prices for works of art using technologies of large language models and deep learning

## Предаукционная выгрузка Christie’s

Python 3.11+.

~~~powershell
python -m pip install -r requirements.txt
python load_christies.py
python -m unittest -v
~~~

Без параметров скрипт ищет очную сессию Christie’s с живописью в текущем и двух следующих месяцах. Дедлайн и диапазон лотов берутся из официального расписания. Скрипт читает все страницы каталога, поддерживает номера с буквенным суффиксом и сохраняет 10–12 подходящих картин из одной сессии. При расхождении числовых границ эстимейта с опубликованной подписью лот исключается, а причина записывается в errors.txt.

Для ручного выбора укажите URL каталога и диапазон лотов внутри одной сессии. Время начала загружается с сайта. Параметр --session-start позволяет дополнительно сверить ожидаемое время с официальным. Если адрес расписания отличается от адреса каталога с окончанием /overview, передайте --overview-url.

~~~powershell
python load_christies.py --catalog-url "https://www.christies.com/en/auction/auction-24268-nyr/browse-lots" --lot-from 701 --lot-to 864 --limit 12 --output-dir ".\snapshots"
~~~

Если в начальном блоке каталога мало подходящих записей, соберите ссылки нужной сессии в текстовый файл по одной на строку и передайте его через --lot-urls-file. При таком запуске техника проверяется по разделу Details карточки лота.

Имя папки включает название аукциона, его публичный номер, диапазон лотов и время сбора в UTC. В папке лежат файлы lots.csv, estimates.csv, errors.txt, фотографии в images/ и контрольные суммы в collection.json. Поле lot_id содержит ID объекта Christie’s, поле sale_id — внутренний ID аукциона.

В lots.csv каждая запись занимает одну физическую строку. Переносы в текстах записаны как `\n`, исходные обратные косые черты — как `\\`. Для Excel используйте импорт «Из текста/CSV» с UTF-8 и разделителем «запятая». Если Christie’s отдельно приводит размеры работы и рамы или холста, сохраняются обе строки с исходными подписями.

Если подтверждено меньше десяти лотов или сбор прерывается, папка попытки имеет суффикс .incomplete. Чтобы сохранить снимок на Google Диск, скопируйте туда всю папку или задайте путь к синхронизируемому каталогу через --output-dir.

## Хранение и передача в анализ

Загрузчик рассчитывает историю во временной папке и публикует снимок для анализа после проверки дедлайна, соответствия lot_id и покрытия архивных источников. Признак готовности — analysis_ready_at_utc в collection.json. Только после этого загружающая команда очищает просроченные неизменённые папки в том же --output-dir. При неполной истории материалы диагностики остаются в .incomplete. Папки с ручными изменениями, дополнительными файлами или без манифеста требуют ручного решения.

Перед основным анализом сохраните выбранные лоты командой mark-used. Она принимает только готовый снимок с проверенными контрольными суммами и создаёт пакет в used/. Функция archive_used_lots(snapshot, lot_ids) предоставляет те же операции из Python.

~~~powershell
python load_christies.py mark-used ".\snapshots\имя выгрузки" --lot-id 6614232 --lot-id 6614233
~~~

Агентам 1 и 2 передавайте только blind/lots.json и blind/images/. Поля с текущими ценами и ссылками исключаются, ценовые строки удаляются из текста, фотографии сохраняются без исходных метаданных. Закройте агентам доступ к сети и родительской папке пакета. Арбитру дополнительно передавайте arbiter/estimates.json. Соединение идёт по sample_id, а audit/ хранит источники и соответствие sample_id исходным lot_id. При перспективном эксперименте фиксируйте выбор лотов и прогнозы до prediction_deadline_utc. Архив, сформированный позже, можно использовать при ретроспективной проверке. Время архивирования записывается отдельно.

## Пятилетняя справка для второго агента

До публикации снимка загрузчик строит artist_history.json. Для каждого lot_id в файле указаны число найденных продаж живописи автора, средняя цена, медиана, квартиль 25% и квартиль 75%. Цены сгруппированы по исходной валюте. Для проверки приложены использованные лоты, даты, техника, размеры и ссылки на Christie’s.

Модуль ищет в публичных каталогах завершённых очных и онлайн-аукционов Christie’s с названиями, указывающими на живопись или соответствующие художественные категории. Учитываются положительные опубликованные Price realised, включая премию покупателя. Границы пятилетнего окна вычисляются от первого времени сбора текущего снимка. У очных торгов граничные даты исключаются, поскольку архивные данные не всегда позволяют установить точное время продажи конкретного лота. Если источник недоступен, справка перечисляет ошибки и помечает охват как partial. Нулевое число означает отсутствие подходящих записей в доступной выборке Christie’s.

Раздел hammer_comparables содержит только явно опубликованные цены молотка. В него входят работы того же автора с совпадающим основным материалом и площадью от половины до двойной площади целевого лота при однозначных размерах в сантиметрах. Если таких наблюдений нет, статус unavailable. Рыночные статистики Price realised остаются в аудите.

Расчёт может занять несколько минут. Флаг --skip-history сохраняет только каталог и не помечает его готовым для анализа. Для ретроспективной проверки существующего снимка:

~~~powershell
python artist_history.py ".\snapshots\имя выгрузки"
~~~

Команда создаёт отдельный файл с суффиксом .history-backfill.json рядом со снимком. Предаукционные данные остаются зафиксированными. Снимки прежней версии можно сверять ретроспективно. Для использования в новом протоколе выполните свежую выгрузку до официального дедлайна.
